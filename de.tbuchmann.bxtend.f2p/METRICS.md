## Methodology

- Only `.xtend` files under `src/` are considered; all other file types are ignored.
- `package` and `import` lines are stripped from every counted file before any metric is computed.
- `Elem2Elem.xtend` is excluded entirely — identical-shape abstract base rule class in every example, would be generator output.
- `<Example>Transformation.xtend` is counted, minus its generated-skeleton methods: `addRules`, `addRulesBwd`, `addRulesFwd`, `checkCorrespondences`, `deleteUnreferencedSourceElements`, `deleteUnreferencedTargetElements`, `detectSourceDeletions`, `detectTargetDeletions`, `new`, `sourceToTarget`, `targetToSource`. Everything else in that file (notably `synch()`, and any project-specific helper) is hand-written and counted.
- LOC = non-blank, non-comment lines. Comment lines include `//` lines and `/* ... */`/Javadoc blocks (tracked line-by-line).
- Words/Characters in the code metrics are computed from LOC lines only — comment text is excluded from those totals and reported separately under Comments.
- Words = whitespace-split tokens. Characters counted both including and excluding internal whitespace.
- Methods = `def`/`override`/constructor (`new(...)`) signatures found in the counted scope.
- This is a heuristic brace-depth/regex-based counter tuned to this codebase's formatting conventions, not a certified SLOC tool.
